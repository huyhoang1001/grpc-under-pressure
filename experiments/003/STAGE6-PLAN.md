## Implementation gap and versioned resolution

The primary CLI rejects deadlines other than2s and Rust atomically claims a single RPC. Eight copies would incorrectly create eight workers/budgets. The versioned `secondary/` runtime copies the accepted source; primary files/binaries are untouched. It adds configurable immutable deadlines, partition ownership, deterministic backoff, and a bounded eight-stream adapter around **one original shared ledger/admission32, staging1, serial worker, FIFO, sweep, logger and response writer**. One decode reservation precedes round-robin polling of up to8 streams; only one selected Work is decoded/staged. Response routing uses the immutable original's client ID. EOF is global only after every stream half-closes. Any stream failure cancels the whole secondary run and its unfinished work, rather than allowing an ambiguous partial study. No per-stream worker/admission budget is created.

Each transport response bridge remains capacity1: aggregate bridge capacity8 in StudyB versus1 in single-client runs. Terminal32/immediate32, global staging1 and event ring1024 are unchanged. Each independent client retains outstanding33, pending/retry32, response64, event1024, bounded original/attempt arrays2880/8640 (the copies retain global indexes for identity). Thus StudyB has aggregate outstanding<=264, pending<=256, response notifications<=512 and event capacity<=8192; at most520 pending/outstanding original ownerships, not a process-RSS bound. Global server original/attempt limits stay2880/8640, queued+running<=32, staged<=1. Attempt IDs use client_id+j*client_count; at most1080 attempts/client in StudyB, global IDs<8640, no collision. Eight manifest/ledger copies and eight HTTP/2 connections are recorded costs, equal in both B variants. Eight transport windows are not a bound on process memory.
