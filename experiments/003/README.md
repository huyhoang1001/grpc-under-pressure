# Experiment 003 — Stage 1 only

Normative documents are [EXPERIMENT-003.md](EXPERIMENT-003.md), [PROTOCOL-003.md](PROTOCOL-003.md), and [VALIDITY-003.md](VALIDITY-003.md). They were copied from the supplied originals. Only the user-approved local-outbound-progress clarification in PROTOCOL §4 and VALIDITY T06 changed; the experiment contract is byte-identical.

This is a protocol/ledger correctness skeleton, not the four-policy application or a performance experiment. No WAIT/REJECT/RETRY/DROP selector, overload refusal/drop path, retry scheduler/backoff, adaptive admission, or benchmark matrix exists. The skeleton uses cancellable bounded staging/admission so protocol ownership can be tested. Stage 2 will attach policies to these shared primitives. Timing calibration, full per-run metric instrumentation and primary-run validity tooling remain later stages.

## Layout

- `proto/overload.proto`: `pressure.e3.v1.OverloadService/Exchange`, bidirectional Work/CancelOriginal/ClientDone and TerminalOutcome/ProtocolError. No ACCEPTED or consumption ACK. `TerminalReference` implements the specified duplicate-result reference, preserving original terminal timestamp/sequence/outcome.
- `server/`: isolated Rust/tonic crate and lockfile; fixed metadata, FIFO single worker, deadline/cancellation ownership, bounded independent outbound writer and event logger; loopback executable for correctness fixtures.
- `client/`: isolated grpc-go module, generated bindings, bounded pending/outstanding/response/event ledgers and independent receive path, immutable manifest and deterministic reconciliation; `cmd/smoke` sends two originals only.
- `fixtures/`: protobuf regeneration, checks and two-message cross-language fixture, not a load generator.
- `STAGE1-REPORT.md`: acceptance/test evidence and scope/deviations.

## Ownership and boundedness

The Rust core serializes registration/admission/state transitions under one lock. Identity records and attempt records have fixed allocations2880/8640, at most3 distinct attempts per original, no eviction and no payloads in the identity/attempt tables. Manifest expectations are immutable. Payload length/hash, original fields, run and attempt identity are checked before registration. Changed identity and cross-original attempt aliasing are errors. Active duplicates join bounded attempt records; completed duplicates replay the original terminal reference, never start new service.

Admission is32 **including** queued and running/cancellation-pending. A cancellation-pending running job remains one running slot, not an additional slot. Acquisition/release counters are checked against physical owned jobs. Each admitted job has one of32 terminal slots before joining the FIFO. Worker completion/removal releases admission independently of response delivery. Terminal capacity remains until writer acceptance or stream failure. Duplicate/waiting-expiry responses reserve one of32 immediate slots even while awaiting the original's result; there is no hidden ready-response spill in the larger attempt table. The one receive lease is shared between pending decode and one staged request; `receive_stage_reservation + decoded_staging <= 1`. Payload bytes for admitted queued/running/staged owners are reported; transient decode bytes can reside in the single receive lease. Invalid oversized wire messages are capped at1MiB, separate from the16384-byte valid payload.

The writer owns at most one frame, plus a capacity1 tonic bridge (transport-side buffering), and never waits for admission. The one-second timeout measures blocked **local** outbound progress, including the deterministic writer barrier. It is not client consumption detection. Hooks default open and are only deterministic fault barriers, not policy tuning. Stream failure preserves completed records, classifies unfinished work and records undelivered results; no new terminal frames are generated after failure. Any already-constructed frame is not a receipt guarantee.

Each process has a fixed1024-event buffer, with contiguous sequence numbers and an append-only JSONL writer. Full server logging blocks before ledger mutation and can be canceled. Full client event logging cancels the operation explicitly/marks the run invalid instead of silently dropping it. File-I/O failure/unresolved shutdown is an explicit invalid snapshot, not successful execution. Record-storage byte estimates include fixed tables and immutable identity metadata, not allocator/transport/RSS totals. All operational queues have fixed bounds; tests may collect a finite, capped fixture transcript.

Under amendment A01 the Go pending heap remains32 and outstanding credits are33 (previously32). This is the minimum headroom over server admission32; see AMENDMENT-A01-REPORT.md. A is recorded at initiation, before Send; successful Send is tracked separately and never means server admission. Receive updates the ledger and returns credit without waiting on Send; response notifications are capacity64 with an independent drainer, and overflow explicitly cancels/invalidates. Replayed terminal frames are idempotent and never return credit twice. Local outstanding expiry retains credit until terminal/definitive stream close; it does not infer server execution phase. Stream failure does not turn unknown delivery into rejection, and there is no ambiguous-delivery retry. Reconciliation iterates all immutable originals, preserves client observation, lets a later authoritative completion supersede an earlier refusal/timeout, checks populations and exposes ACK-missing/UNKNOWN independently.

## Timing, transport and error decisions

Deterministic unit tests supply explicit monotonic offsets; runtime service uses a single Tokio monotonic epoch. Service delay is chosen at worker start (10/40/10ms). Queued/waiting deadlines remove actual ownership; running cancellation records request/observation/exit and retains the permit through delayed checkpoints. Completion exactly at deadline is on time; a completion winning before cancellation observation can be late. No start after deadline.

The two-process fixture supplies a common future epoch via CLI (no partially published marker); ready-file publication uses an atomic rename. This is a smoke-test coordination mechanism, **not** Stage 3's <5ms clock calibration or a valid performance run. The offline2880-ID partition in that fixture uses a **synthetic**39s cutoff; it does not run39s or generate2880 arrivals. Only two messages are actually sent.

The Go fixture pins static65535 stream/connection windows, max message1MiB, no compression, configured retries disabled and replay-buffer size0. grpc-go's WithDisableRetry alone still permits pre-commit transparent establishment retries. The fixture waits for initial response headers **before Work**, committing the RPC in the pinned grpc-go implementation; no automatic application Work replay follows that commit. This is transport establishment, not a new per-message or client-consumption ACK. Stage3 must still instrument/validate connection/stream/byte behavior before primary runs.

Protocol-invalid identities/control frames are fail-stop, using correlated ProtocolError when IDs are known; no overload-policy terminal is invented. One stream is allowed per Stage1 run, no reconnect/durable dedup guarantees. `ClientDone` is diagnostic; only actual send half-close signals EOF. Normal EOF continues response draining. Per-message terminal sequence/timestamp stays stable across duplicate replay. The server-ledger snapshot is authoritative in the fixture; local write acceptance alone never clears client ACK-missing.
